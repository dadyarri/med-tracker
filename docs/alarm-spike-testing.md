# Alarm spike: проверка на Samsung

Этап 1, без медицинских данных. Целевое устройство: Samsung, Android 16 / One UI 8.5.
**Физическое устройство в облаке отсутствует: все пункты ниже пока НЕ проверены.**

## Установка и APK

GitHub Actions → Android APK → успешный запуск → Artifacts → MedTracker-debug-… .
Распаковать артефакт и установить `app-debug.apk`. Разрешить установку из выбранного
источника. Для обновления без удаления данных нужен тот же сертификат подписи.
Workflow использует временную debug-подпись runner-а: между запусками она может
отличаться. Для теста обновления соберите обе версии на одной машине с сохранённым
`~/.android/debug.keystore`. Не удаляйте приложение ради обхода несовпадения подписи,
если важно сохранить локальное состояние. Стабильная release-подпись пока не настроена.

## Реализация и ограничения

Один тест (строка Room id=1), append-only журнал последних событий, DataStore для
мастера. Нет сервера, сети приложения, аналитики, резервного копирования и меддомена.
AlarmManager.setAlarmClock используется и для тихого, и для звукового теста.
Системный значок следующего будильника может появляться и у тихого теста.
Полноэкранное отображение и запуск foreground mediaPlayback-службы контролирует ОС.
Reboot/update receiver только согласует будущие PendingIntent, не запускает UI/аудио.
Обработка после первого разблокирования пользователя; Direct Boot не заявлен.
Недоставленное при выключенном устройстве событие не записывается как доставленное.
«Доставлен receiver-у» не означает доказанный звук или показ уведомления пользователю.

Автоматические JVM-тесты проверяют сроки, grace window, замену/stale token,
идемпотентное восстановление, отсутствие backlog, snooze/лимит и границы окна.
Они не подтверждают фактическую работу Android API или Samsung.
