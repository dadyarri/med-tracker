# MedTracker

Персональное офлайн-приложение для Android 16+. Реализованы мастер разрешений,
механизм напоминаний, давление (этап 2 принят владельцем), вес и глюкоза,
общая история, графики, статистика и фильтры (этап 3, ручная приёмка ожидается).
Спецификация: [docs/specification.md](docs/specification.md).

- Kotlin, Jetpack Compose / Material3 с системной темой и динамическими цветами.
- Room — измерения, питание, цикл и задачи напоминаний; DataStore — мастер, расписания и звук будильника; Koin — зависимости.
- Application ID `dev.dadyarri.medtracker`, min SDK 36, target/compile SDK 37.
- JDK 21; JVM target 17; Gradle 9.8.2, AGP 9.5.0 со встроенным Kotlin,
  Compose compiler 2.4.21 и KSP 2.3.13.
- Нативный `AlarmManager.setAlarmClock`, foreground mediaPlayback и уведомления.
  Нет сервера, сети приложения, аналитики и резервного копирования.

## Проверка на телефоне

Версия `0.5-measurements` (versionCode 6) открывает пошаговый мастер разрешений:
уведомления, будильники, полноэкранные уведомления и работа в фоне.
Каждый шаг можно пропустить. Отдельный шаг настройки Samsung удалён по решению владельца.
После завершения открывается «Сегодня» с навигацией «Сегодня / История /
Лекарства / Настройки». В «Сегодня» — записи и пунктирные карточки плана за
текущий день, фиксированные кнопки давления, веса, глюкозы и еды. В «Истории» — общая хронология по датам,
фильтры типа/периода/контекста, графики и статистика. Тап открывает редактор;
удаление требует подтверждения. «Лекарства» пока пустые. В «Настройках» —
расписания давления, веса, питания, цикл глюкозы и общая мелодия будильника.
Включение напоминаний регистрирует точный будильник; совпавшие сроки объединяются.
Звуковой сигнал запрашивает полноэкранный режим, если он разрешён Android.
Основное действие будильника и нажатие уведомления открывают отдельную форму
поверх предыдущего приложения. Сохранение записи завершает выбранную задачу;
открытие/отмена формы ничего не подтверждает.
Поведение, ограничения и ручной чеклист: [docs/reminder-settings-testing.md](docs/reminder-settings-testing.md).
Завершение мастера сохраняется в DataStore; обновление не сбрасывает его.
Экран постановки тестовых сигналов удалён по согласованному изменению интерфейса.
Механизм сигналов, Room и существующее состояние сохранены.

Обязательный ручной протокол и ограничения:
[docs/alarm-spike-testing.md](docs/alarm-spike-testing.md).
Основной чеклист alarm spike отмечен владельцем как пройденный на Samsung.
Этап давления принят владельцем: [docs/pressure-testing.md](docs/pressure-testing.md).
Проверки этапа 3 и ручной чеклист: [docs/measurements-testing.md](docs/measurements-testing.md).

## Сборка

Установить полный JDK 21, Android SDK с `platforms;android-37`,
`build-tools;36.0.0`, `platform-tools`, `ndk;29.0.14206865`;
задать `JAVA_HOME` и `ANDROID_HOME`.
Путь SDK также можно указать в игнорируемом `local.properties`.

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Отчёты: `app/build/reports/`. JVM-тесты включают чистую политику расписания
и Android API 36/Room через Robolectric. Они не подтверждают звук, экран
блокировки, энергосбережение или особенности физического Samsung.

В подготовленной облачной среде перед Gradle:

```sh
source /workspace/toolchains/env.sh
cd /workspace/med-tracker
```

## GitHub Actions

Workflow **Android Release Build** запускается при push в `master` и вручную
для `master`. Он выполняет `assembleRelease testDebugUnitTest lintRelease`
на JDK 21 с тем же Android SDK/NDK, что и debug CI. После успешных проверок APK
подписывается постоянным release-ключом через apksigner; подпись проверяется.
В GitHub Releases публикуется `build-<run_number>`, привязанный к точному SHA
сборки. Файлы: `MedTracker-release.apk`, `signing-certificate.txt`, `SHA256SUMS`.
Сначала создаётся черновик с файлами, затем релиз публикуется и отмечается Latest.
Повторный запуск дополняет черновик, но не перезаписывает опубликованный релиз.
Ключ удаляется с runner после выполнения, в том числе при ошибке.
Права `contents: write` выданы только release-job; PR не запускает этот workflow.

Перед первым запуском владелец вручную добавляет в Settings → Secrets and
variables → Actions → Repository secrets четыре секрета:

| Secret | Значение |
|---|---|
| `ANDROID_RELEASE_KEYSTORE_BASE64` | Постоянный release-keystore, закодированный Base64 |
| `ANDROID_RELEASE_KEY_ALIAS` | Alias ключа внутри keystore |
| `ANDROID_RELEASE_STORE_PASSWORD` | Пароль keystore |
| `ANDROID_RELEASE_KEY_PASSWORD` | Пароль приватного ключа |

Base64 не шифрует ключ: используйте именно Secrets, не Variables, исходники
или сообщения в чате. Храните оригинал keystore и пароли вне репозитория.
Workflow не генерирует новый ключ и не подставляет debug-ключ при отсутствии
release-secrets: он завершается ошибкой до сборки. Значения секретов не выводятся.
Secrets настраиваются владельцем через интерфейс GitHub.

Release с другим сертификатом не обновит существующую debug-установку.
Не удаляйте приложение с медицинскими данными ради смены подписи; переход
между сертификатами требует отдельного решения. Версия и versionCode берутся
из `app/build.gradle.kts`; тег сборки сам по себе версию приложения не меняет.

Проверка конфигурации: `assembleRelease testDebugUnitTest lintRelease` — exit 0,
5s (часть задач из кеша). Команды проверки паролей и подписи проверены локально
на временном тестовом ключе: `apksigner verify` — exit 0, схема v3.
Публикация настоящего релиза проверяется после настройки Secrets и push в master.

Workflow **Android APK** запускается при push в `master`/`feature/**`, в PR
и вручную (`workflow_dispatch`). Он собирает debug APK, выполняет unit tests
и Lint и сохраняет `MedTracker-debug-<run>` и `checks-<run>` на 14 дней.
APK доступен после успешного запуска в Actions → Android APK → Artifacts.
Артефакты GitHub скачиваются ZIP-архивом; перед установкой извлеките APK.

Debug APK предназначен для тестирования. CI требует постоянный ключ из GitHub Secret
`ANDROID_DEBUG_KEYSTORE_BASE64`: без него workflow останавливается вместо генерации
новой несовместимой подписи. В Artifacts рядом с APK находится публичный сертификат
`signing-certificate.txt`; его SHA-256 должен совпадать у обновляемых сборок.

Однократная настройка на своей машине (JDK 21, GitHub CLI с правом управления
секретами репозитория):

```sh
./scripts/configure-ci-signing.sh
```

Скрипт сохраняет тестовый ключ вне checkout и передаёт его в GitHub Secret через stdin.
Повторный запуск использует тот же файл. Для уже сохранённого стандартного debug-ключа:

```sh
./scripts/configure-ci-signing.sh /path/to/existing/debug.keystore
```

Ключ: alias `androiddebugkey`, store/key password `android`. Это тестовая подпись,
не release signing. Храните приватный keystore надёжно, не добавляйте его в Git
и не присылайте значения секрета в чат. Для локальной сборки с той же подписью
используйте этот ключ как `~/.android/debug.keystore`, предварительно сохранив
существующий файл; не заменяйте другой нужный ключ без резервной копии.

Старые CI-сборки использовали случайную подпись каждого runner-а. Если её приватный
ключ не сохранён, обновить такое приложение новой подписью без удаления нельзя.
Однократная переустановка удалит локальные данные, настройки и выданные разрешения;
сначала настройте постоянный ключ и получите успешный CI, затем решите вопрос переноса.
Подмена сертификата, увеличение versionCode или восстановление одной лишь публичной
части сертификата не исправляют несовместимость подписей.
